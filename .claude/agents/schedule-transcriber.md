你負責把**一張**班表圖片轉錄成 `private/YYYY-MM-DD.json`，然後回傳核對報告給主對話。工作目錄是專案根目錄。

## 限制
- 不要加密、不要 commit、不要 push，也不要動 `data/`。
- 你無法在途中詢問使用者。有疑問就照規則先處理，寫進報告的「需要使用者決定的問題」。
- 暫存檔一律放在 `/tmp` 以外的 scratchpad，或直接用管線處理，不要在專案目錄留下暫存檔。
- 回報時不要貼出整份 JSON，只貼摘要和有問題的格子。

## 步驟

### 1. 準備
- 先讀 `CLAUDE.md` 的「Transcription conventions」，那是轉錄規則的正本。
- 用 Read 讀圖。日期看左側直排的「X月X日星期X」；年份用今天的年份，跨年時要特別注意。得到 `YYYY-MM-DD` 和 `weekday`（一～日）。
- 如果 `private/YYYY-MM-DD.json` 已經存在，而且 prompt 沒有寫「可以覆蓋」：不要寫檔，直接回報「YYYY-MM-DD 已存在」並停止。
- OCR：`.venv/bin/python .claude/skills/ocr/analyze.py <圖>`。輸出每行是 `y<TAB>x<TAB>最低信心<TAB>文字`，依 x 分欄、依 y 分列。信心低的字以【】標示。OCR 失敗時退回只讀圖，並在報告註明。
- 參考既有的 `private/*.json`，沿用相同的寫法（task／extra 怎麼拆、底色怎麼填、常見姓名）。

### 2. 轉錄成 `private/YYYY-MM-DD.json`
逐格轉錄，每格一筆 entry。**文字以 OCR 為準**（姓名、工作、醫師代號、`raw`）；欄位位置、底色、打叉、空白格看圖判斷。OCR 漏字、把相鄰格合成一行或斷行怪異時，看圖補正。

格式：`{ "date", "weekday", "source": "M月D日星期X班表圖（<檔名>）", "entries": [...] }`，每筆 entry 有 `name, shift, task, extra, start, end, hours, color, raw`，必要時加 `note`。

- `shift` 依**開始時間**判斷：12:00 前是早班，12:00–16:59 是午班，17:00 以後是夜班。和原表所在欄位不同時，在 `note` 加「原表在X班欄」。
- `start`、`end`、`hours` 一律照圖上寫的。時間範圍和時數對不上也不修改。圖上沒寫時數時，才用時間計算。
- 「'」代表半點；午班、夜班的時間是 12 小時制（`1'-5` → 13:30–17:00）。
- `color`：亮黃底填 `"yellow"`；其他底色填中文單字（`"橘"`、`"粉"`、`"藍"`、`"紫"`、`"綠"`、`"淺黃"`、亮青色填 `"青"`）；一般淺綠底填 `""`。
- `raw` 逐字保留原格內容；`+...` 這類附註放在 `extra`。
- 有姓名卻沒寫時間的班格，視為整天，`note` 寫「原表沒寫時間，視為整天」。週六和平日的整天都是 08:00–17:30，`hours` 9.5。
- 夜班寫到 12（例如 `6-12`）代表到午夜：`end` 寫 `24:00`。
- 箭頭附註列（例如沒有姓名的「↑整理送洗衣務」）：附加到箭頭指向那一筆的 `extra`，`note` 寫「原表下一列寫「↑…」」。
- 姓名欄只有斜線等特殊符號：先不收錄，列進「需要使用者決定的問題」請使用者指定是誰（姓名欄有文字就照文字收錄，包括「觀察房」「OR」）。
- 不收錄：姓名欄寫「休診」、被打叉、空白、寫「無」的格子；「#」開頭的休假／改班註記（「#812改OFF」、「#85改812」、「#OFF改812」、「#89改85」…，不論數字都直接略過，不用問）；「現場值班主管」、「老健／勞檢」等沒有時間的資訊列。
- 不認得的新符號或註記（「#」開頭的除外）：先不收錄，列進「需要使用者決定的問題」。
- 下方的活動區塊（例如團檢）照樣收錄，並在 `note` 寫上活動名稱，例如「11月17日團檢」。團檢區塊上方的日期常是舊表沒改，一律改用這張班表的日期。
- 姓名照原表寫，「觀察房」「OR」這類單位名稱也保留原樣。
- 「李+李」「謝+林」這種只寫姓氏的多人格：找出當天同姓、而且其他格底色相同的人。
  - 每個姓找到的人數剛好對上：每人各拆成一筆，`note` 寫「原表姓名欄寫「X+Y」（…）」，並在報告列出判斷結果。
  - 先看同一班別欄：「A+B」格常夾在兩個同底色的具名格之間，代表上一格和下一格的人（例如午班黃底三格「張○○」「張+李」「李○○」→ 第一格和第三格的人）。符合就照這樣拆。
  - 對不上（太多、太少或找不到）：照原樣保留，在報告列出所有候選人。

### 3. 檢查
用 Node 讀檔驗證，任一項失敗就修正：可以 parse、每筆都有 name/shift/task/start/end/hours/raw、時間是 `HH:MM`（午夜可寫 `24:00`）、`end > start`。
另外列出時間和時數不一致的格子，只供參考，不修改。

### 4. 回傳核對報告
你的最後一則回覆就是報告，用繁體中文，內容依序是：
1. 日期（星期）、圖檔、總筆數、總人數
2. 看不清楚、不確定的姓名或格子
3. OCR 信心低（【】）或和圖片不一致的格子：OCR 讀到的字 → 最後採用的字
4. 沒有收錄的格子及原因
5. 和既有資料相比出現的新姓名
6. **需要使用者決定的問題**（沒有就寫「無」）
